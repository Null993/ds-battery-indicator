## 电量函数确实是档位换算

1. 托管接口 `PSAccessories.LibFWupdater.GetBatteryLevel(int handle)` 通过 P/Invoke 调用 `libFWupdater`。
2. 导出 `GetBatteryLevel` 位于 RVA `0x15E0`。它调用 RVA `0x3CE0`，获取状态和一个字节值，返回这个字节；错误状态返回 -1。
3. RVA `0x3CE0` 的设备分支调用 RVA `0x8600`。该判定只对 Sony VID `0x054C`、PID `0x0CE6` 或 `0x0DF2` 返回 true。因此被分析的分支针对 DualSense / Edge，不是误读其他型号分支。
4. RVA `0x3DCA` 读取内部状态缓存中的一个字节（缓存偏移 `0x88`），RVA `0x3DD5` 提取低四位，RVA `0x3DD8` 比较最高档 10。
5. 档位 0–9 的跳表目标是 RVA `0x3DF3`，执行等效 `10 * level + 5`；档位 10 的目标 RVA `0x3E05` 写入 `0x64`（100）。跳表位于 RVA `0x40AC`，应作为数据而非指令解释。

关键算术指令：

```text
RVA 3DF3  and cl, 0x0f
RVA 3DF6  movzx eax, cl
RVA 3DF9  shl al, 2       ; 4 * level
RVA 3DFC  add cl, al      ; 5 * level
RVA 3DFE  add cl, cl      ; 10 * level
RVA 3E00  add cl, 5       ; +5
RVA 3E05  mov cl, 0x64    ; 最高档分支，100
```

解释：官方程序该路径也把分档值转换成中值百分比，没有从这个函数得到真实 1% 精度。

限制：本轮没有追踪内部缓存 `+0x88` 的所有生产者，也没有证明整个官方库永远没有其他测量接口。该分支还有版本门槛和错误处理，本分析针对已识别的 DualSense 档位转换路径。静态反汇编不是在真实运行环境单步执行的记录。

## Telemetry 是统计信息，未见瞬时电池测量

原生库共 54 个导出，包括 `GetTelemetryDataDualSense` / `GetTelemetryDataDualSenseEdge`，但没有命名为 ReadBatteryVoltage / ReadChargeCurrent 的导出。名称缺失只是线索，不是不存在接口的证明。

托管声明的 `TelemetryDataDualSense` 字段包含：

- `totalActiveTime`、`totalChargeTime`；
- `batteryChargeCount`、`batteryChargerConnectCount`、`batteryFullChargeCount`；
- `batteryChargeVoltageErrorCount`、`batteryChargeTemperatureErrorCount`、`batteryChargePmicErrorCount`；
- USB 类型识别、连接次数、认证统计和按钮/摇杆使用统计。

没有识别到瞬时 V、A、W 的字段。`batteryChargeVoltageErrorCount` 的类型为 byte，是异常计数，不能误读成电池电压。字段名中 `Current` 也可能表示“当前摇杆模块”，不是电流。

静态调用路径：导出 RVA `0x3640` 检查控制器与版本后，调用 RVA `0x3400`。该例程的 RVA `0x3496` 写入 `0x7080`，随后 RVA `0x349E` 写入 `0x01`，构成 64 字节 Feature 请求 `[0x80,0x70,0x01,0,...]`。它随后读取 `0x81`，检查响应状态并组装最多六段、每段 56 字节数据。

这条路径提供一个有实证的工厂统计协议示例，**不是 Power=2 的电压/电流读取命令**。本轮没有发送该请求，也没有采集其中的设备序列号或用户使用统计。

## 保存位置与重现

- `research/artifacts/sony-app-string-scan.json`：根目录 DLL/EXE 的关键词筛选结果与哈希；通用 SDK/ICU 中的 battery/voltage 命中不作手柄证据。
- `research/artifacts/sony-managed/`：本机官方托管库的 ILSpy 输出。
- `research/artifacts/sony-native/`：PE 导入/导出、RVA 范围反汇编及本地原始库快照。

```powershell
research/artifacts/tools/ilspycmd.exe -p -o research/artifacts/sony-managed "C:/Program Files/Sony/PlayStationAccessories/PlayStationAccessories.dll"
python research/inspect_sony_native.py "C:/Program Files/Sony/PlayStationAccessories/libFWupdater.dll" research/artifacts/sony-native --rva 3ce0 --rva 8600 --rva 3400 --range 3400:3640
```

反汇编工具的 Windows unwind 记录只能提示代码范围。部分函数具有分开的代码块；RVA `0x3400` 的第一次范围输出不完整，因此另保存了明确范围 `0x3400..0x3640`。无 unwind 的叶函数输出可能包含相邻函数，跳表会被线性反汇编器误解释；分析时按分支地址和数据布局区分。没有把这些输出直接当成准确的高级源码。

下一步最有价值的是定位官方库/固件中的工厂 Power action 表，以及只读电池测量命令。当前证据足以排除“直接改调官方 GetBatteryLevel 或统计 Telemetry 就能获得精确电量/实时充电瓦数”的方案。
